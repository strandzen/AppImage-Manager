# Contributing to AppImage Manager

## Building

### Dependencies

See **Build dependencies** in [README.md](README.md#other-distributions) for Arch, Fedora, Debian/Ubuntu and openSUSE.

### Build and install

```bash
cmake --preset dev
cmake --build --preset dev
ctest --test-dir build/dev --output-on-failure
sudo cmake --install build/dev
```

On Arch, `cd packaging && makepkg -sif` builds this checkout as a pacman package instead.

### Clean rebuild

```bash
rm -rf build/ && cmake --preset dev && cmake --build --preset dev
```

## Architecture

| Target | Type | Description |
|--------|------|-------------|
| `appimagemanager_core` | Object library | Pure C++, no QML. `AppImageReader`, `AppImageCache`, `AppImageManager`, `AppImageInfo`, update sources, launch environment |
| `appimagemanager_qml` | QML module | GUI backend classes (models, `AppSettings`, `ReleaseChecker`, update manager, daemon) + QML files (all windows and dialogs) |
| `appimagemanager` (binary) | Executable | Dashboard, manage window for one file, or `--daemon` |

**One binary, three modes.** Dolphin's Open With (the `MimeType=` in the `.desktop` file) runs `appimagemanager <path>`, which opens `AppImageWindow::open(path)`. Without arguments the binary opens the dashboard; `--daemon` runs the background update checker.

**Data flow:**
```
AppImageWindow::open(path)
  └─ AppImageBackend(path) — emits metadataLoadedChanged
       └─ QtConcurrent::run(AppImageReader(path).read())   ← worker thread
            └─ AppImageInfo (value struct)
       └─ onMetadataReady → updates Q_PROPERTY → QML binds
```

**Dashboard entry point:** `DashboardWindow::open()` is a singleton that creates its own `QQmlApplicationEngine`, `AppImageListModel`, and `AppImageSortFilterModel`. It is opened by `appimagemanager` with no arguments.

## Project Layout

```
src/
  core/           Pure C++ logic (no Qt Quick dependency)
  gui/            Backend classes exposed to QML + window hosts
qml/              All .qml files (registered as QRC resources)
po/               gettext translations; .pot generated by cmake
po-drafts/        unreviewed translation drafts, not built (see Translations)
data/             Desktop entries, notifications, icon, metainfo, D-Bus service, tray widget
```

## Branching and Commits

- **`main`** is always releasable. Direct commits are fine for small fixes.
- For larger features, open a short-lived feature branch and merge via PR.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):

  ```
  feat: add storage usage dialog
  fix: center icons correctly when app is installed
  refactor: extract createBackend() helper in DashboardWindow
  docs: update README build instructions
  chore: add CMAKE_EXPORT_COMPILE_COMMANDS to dev preset
  ```

  Types: `feat`, `fix`, `refactor`, `docs`, `chore`, `style`, `test`

## Code Style

- C++20, Qt6, KDE Frameworks 6 conventions.
- Blocking I/O (`AppImageReader`, corpse scan) always runs via `QtConcurrent::run`.
- User file deletion goes through `KIO::trash()`, never `QFile::remove`.
- QML context properties (not creatable types) expose C++ to QML.
- No raw `new` without a parent or immediate `unique_ptr`/`QScopedPointer`.

## Translations

Strings are wrapped in `i18n()` (QML) or `i18n()` / `tr()` (C++, prefer KI18n).
The `.pot` template is regenerated by CMake (`ki18n_install`). For now the app ships in
English only: machine-made drafts for 15 languages wait in `po-drafts/<lang>/` (marked fuzzy,
not built). To finish one, review it, remove the `fuzzy` marks and move the folder to
`po/<lang>/`. To add a new language, copy `po/appimagemanager.pot` to
`po/<lang>/appimagemanager.po` and translate.
